# Preservation Contract

기술 문장을 고칠 때 문체보다 먼저 지켜야 할 의미 보존 규칙이다.

## 절대 임의로 바꾸지 않는 항목

- 숫자와 범위: `29~40`, `0.15`, `6/6`
- 단위: `ms`, `u/s`, `rad/s²`, `MiB`
- 날짜, 시간, 버전, 커밋
- 코드 심볼: `turnK`, `NS_ROT_MODEL`, `HERO_DISTANCE_K`
- 명령어, 옵션, 파일 경로
- 상태 이름, enum, API 필드
- 오류 메시지와 로그 문자열
- 공식 제품명과 프로젝트 고유명

표기를 통일해야 한다면 값 자체가 아니라 주변 문장만 고친다.

## 검증 수준을 승격하지 않는다

다음은 서로 다른 상태다.

- 계획했다
- 구현했다
- 실행했다
- 관찰했다
- 테스트했다
- 재현했다
- 검증했다
- 배포했다
- 실제 사용자 환경에서 확인했다

원문이 `테스트했다`고만 말하면 `검증됐다`고 쓰지 않는다.

## 인과관계를 새로 만들지 않는다

원문:

> 변경 뒤 프레임 시간이 5.9ms에서 6.3ms가 됐다.

근거가 없다면 다음처럼 쓰지 않는다.

> 변경 때문에 프레임 시간이 6.3ms로 늘었다.

`변경 뒤`, `동시에`, `관찰됐다`는 인과를 뜻하지 않는다.

## 불확실성을 지운다거나 추가하지 않는다

- `가능성이 있다` → `발생한다` 금지
- `원인으로 추정한다` → `원인이다` 금지
- `확인하지 않았다` 삭제 금지
- 근거 없이 `아마`, `대체로`, `분명히` 추가 금지

## 부정과 범위를 보존한다

다음 차이를 유지한다.

- 모두 실패하지 않았다
- 모두 성공했다
- 일부는 실패하지 않았다
- 실패한 항목이 없었다

문장을 자연스럽게 바꾸더라도 논리 범위를 바꾸지 않는다.

## 비교 기준을 보존한다

`2배`, `30% 감소`, `0.4%p 감소`는 기준이 다르다.

- 배수인지 차이인지 구분한다.
- `%`와 `%p`를 바꾸지 않는다.
- 기준선이 무엇인지 원문에 있으면 유지한다.

## 정보 삭제 기준

다음은 삭제할 수 있다.

- 같은 사실의 완전한 반복
- 내용이 없는 메타 표현
- 문서 흐름에 기여하지 않는 장식적 문구

다음은 삭제하지 않는다.

- 재현 조건
- 실패 조건
- 예외
- 한계
- 측정 환경
- 판단에 영향을 주는 수치
- 결과를 해석하는 데 필요한 기준선
