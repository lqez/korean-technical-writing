# Review Checklist

최종 결과를 내기 전에 순서대로 확인한다.

## A. 사실과 의미

- [ ] 숫자와 단위가 원문과 같은가?
- [ ] 코드 심볼, 옵션, 파일명, 버전을 바꾸지 않았는가?
- [ ] 조건과 예외가 남아 있는가?
- [ ] 부정문의 범위가 바뀌지 않았는가?
- [ ] 관찰을 인과관계로 바꾸지 않았는가?
- [ ] 테스트 결과를 검증 완료로 승격하지 않았는가?
- [ ] 확인하지 않은 사실을 새로 만들지 않았는가?

## B. 구조

- [ ] 문서의 목적이 하나로 설명되는가?
- [ ] 핵심 결과가 너무 늦게 나오지 않는가?
- [ ] 한 문단이 하나의 중심 주제를 다루는가?
- [ ] 문제, 변경, 결과, 한계가 뒤섞여 있지 않은가?
- [ ] 제목만 읽어도 흐름을 파악할 수 있는가?

## C. 모호성

- [ ] `이것`, `그것`, `해당`의 대상이 분명한가?
- [ ] `그리고`, `또는`, `및`의 결합 범위가 분명한가?
- [ ] 비교 기준이 명시되어 있는가?
- [ ] `만`, `모두`, `각각`, `최대`의 범위가 분명한가?
- [ ] 긴 명사구가 독자에게 추론을 요구하지 않는가?

## D. 한국어

- [ ] 불필요한 번역투가 없는가?
- [ ] 내부 은어가 필요한 기술 용어로 바뀌었는가?
- [ ] 추상 명사 대신 구체적인 동사를 쓸 수 있는 곳이 있는가?
- [ ] 주어를 억지로 추가하지 않았는가?
- [ ] 모든 문장을 같은 길이와 어미로 만들지 않았는가?
- [ ] 이미 좋은 문장을 불필요하게 바꾸지 않았는가?

## E. 용어

- [ ] 한 개념을 한 이름으로 부르는가?
- [ ] 실제 코드와 프로젝트의 공식 심볼을 우선했는가?
- [ ] 첫 등장 때 설명이 필요한 프로젝트 고유 용어가 있는가?
